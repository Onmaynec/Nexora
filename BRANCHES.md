# Ветвление и история Nexora

## Текущая политика

`main` — единственная постоянная рабочая ветка. Все следующие исправления и изменения проходят проверки и попадают непосредственно в неё. Отдельные release/feature/fix refs, оставшиеся от предыдущей схемы работы, больше не используются.

В `main` могут находиться исходники функций, которые ещё не опубликованы. Merge, прохождение source CI и статус GitHub Release — разные события. Версию нельзя считать выпущенной без immutable tag, подписанных артефактов, внешней проверки и публикационных свидетельств.

## Архив прежних веток

Полный список SHA и принятое решение: [docs/BRANCH_ARCHIVE_2026-11-14.md](docs/BRANCH_ARCHIVE_2026-11-14.md).

Перед удалением прежних refs автоматическая операция сохраняет их commit histories в едином теге `archive/branches-before-main-only-2026-11-14`. Этот тег не считается release tag и не меняет рабочее дерево `main`. Ветку на основе старого SHA разрешено восстанавливать лишь после ревью актуальности кода.

## Правила разработки

1. Все новые изменения оформлять с понятным commit message; не смешивать техническое исправление с публикацией релиза.
2. Для каждого подтверждённого бага записывать воспроизведение, исправление, тест и ссылку на коммит.
3. Проверять Windows/Linux source CI, Android source, схему БД и затронутые security gates.
4. Не публиковать релиз, пока открыты обязательные внешние acceptance gates.
5. `Trust/MLS` — только исторический read-only контур, не возвращать удалённый executable runtime из старых веток.
6. Удаление исторических веток выполнять только после создания и проверки архива и при отсутствии открытых PR.
