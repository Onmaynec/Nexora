# Nexora 3.7.0 — сообщения в каналах Communities

> Состояние: экспериментальные исходники в `main`, стабильный релиз **не опубликован**. Опция `experimentalCommunities` должна быть явно включена оператором Local Server. Текущая package version — 3.6.0 до отдельного процесса release promotion.

## Что реализовано

- Текстовые сообщения в каналах `text` и `announcement`.
- Хранение сообщений в отдельных SQLite-таблицах поверх текущей схемы 10; существующие комнаты/сообщения не изменяются.
- Приватный канал доступен только участникам с `channel.view_private`.
- Обычные участники могут отправлять текстовые сообщения; для канала `announcement` требуется `channel.announce`, которое получают owner, moderator и назначенные пользовательские роли.
- Отправка повторного `clientNonce` тем же автором в тот же канал возвращает существующее сообщение без дубликата; повторное использование с другим текстом приводит к `409 STATE_CONFLICT`.
- Серверный лимит: до 4000 символов на сообщение, до 12 новых сообщений в минуту на пользователя внутри сообщества, не более 50 000 сообщений на канал. Дополнительно действуют базовые лимиты Communities.
- История отдаётся курсорными страницами: `(created_at DESC, id DESC)`, максимум 100 элементов на запрос. При одинаковых временных метках сортировка остаётся определённой.
- Автор может удалить своё сообщение; модератор — сообщения обычных участников. Модератор не может удалить сообщение owner или другого moderator. После удаления содержимое очищается, а метаданные остаются с `deletedAt`.
- При удалении канала его история удаляется.
- UI поддерживает переключение каналов, отправку, историю, удаление и обновление данных каждые 7 секунд, только через авторизованные REST-запросы.

## HTTP API

Все пути начинаются с `/api/v3/communities/:communityId/channels/:channelId/messages`.

| Метод | Путь | Ответ / ограничение |
|---|---|---|
| GET | `/` с `limit=1..100` и необязательным `before` | `{ok,messages,nextCursor}`; доступ проверяется на каждом запросе |
| POST | `/` | `{body,clientNonce}`; статус 201 для новой записи, 200 для безопасного повтора |
| DELETE | `/:messageId` | удаляет текст, фиксирует аудит `message.deleted`; права автора/модератора |

`clientNonce` — UUID, генерируемый клиентом для каждой логической попытки. Для повторения запроса после сетевой ошибки требуется использовать тот же nonce и тот же body.

Сервер возвращает стандартные коды: `AUTH_REQUIRED`, `VALIDATION_FAILED`, `RESOURCE_NOT_FOUND` (в том числе для скрытого канала или бывшего участника), `FORBIDDEN`, `STATE_CONFLICT`, `RATE_LIMITED`, `RESOURCE_LIMIT`.

## Граница приватности и восстановления

- GET/POST/DELETE всегда заново проверяют membership и право просмотра канала. После банa или выхода чтение и запись запрещены.
- Сообщения **не** рассылаются в широкие Socket.IO-комнаты без повторной проверки адресатов; до появления полноценного scoped fanout используется периодическое получение данных. Это намеренное ограничение экспериментальной версии.
- HTML внутри текста не интерпретируется интерфейсом: React рендерит обычный текст.
- Таблицы сообщений создаются только при включённом Communities, схема 10 не повышается. Это не готовая к стабильному релизу миграция и не замена operator backup/restore.
- Удаление канала физически удаляет его сообщения. Удаление отдельного сообщения очищает текст, сохраняя метаданные для упорядочивания истории.
