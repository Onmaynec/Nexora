## Implemented scope

- server-owned contact request lifecycle, contact removal and block/unblock compatibility;
- cursor-paginated privacy-filtered user search;
- presence, last-seen and read-receipt privacy policies;
- authenticated one-to-one Socket.IO call signaling with minimal persisted call history;
- short-lived TURN credentials generated by Local Server;
- WebRTC voice UI with microphone/output selection, mute, timer and terminal media cleanup;
- Server-ID-bound profile deep links and safe generic fallback;
- additive schema 10 migration with backup, transaction, integrity and downgrade protection;
- Connect unit/API/realtime/security regression coverage and version-specific release evidence.

## Current verification state

Release metadata, schema assertions, release notes and version-specific evidence have been synchronized to `3.6.0`. The branch must still pass the complete exact-head CI matrix and the remaining negative/race/security regressions before the PR can leave draft state.

## Security boundary

Local Server is authoritative for contact transitions, privacy visibility, call participant scope, active session binding, block policy, signaling state, payload bounds, rate limits and call history. Voice media is not stored by Local Server. TURN secrets, credentials, SDP, ICE candidates and IP addresses must not appear in logs, metrics, diagnostics or persisted call history.

## External release blockers

- production TURN configuration and operational verification;
- independent security review with no unresolved high/critical findings;
- signed Windows Client/Server and signed Android artifacts;
- Windows 10/11 installed acceptance;
- Windows ↔ Android, Windows ↔ PWA and Android ↔ PWA call acceptance;
- signature, checksum, SBOM, immutable tag and re-download smoke evidence.
